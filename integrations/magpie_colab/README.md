# Magpie Colab DeepSeek integration

This integration adds a Magpie page for the on-demand `llm.py` controller. It displays the controller state and Colab CLI balance and saves settings for the next GPU session. It requires a working Colab CLI OAuth login, a separately configured Magpie OpenAI-compatible provider pointing at the controller's loopback endpoint, and a local service manager. Installation of this plugin alone does not configure those dependencies or authenticate Colab.

## Components

- `controller.py serve` wraps the project controller, reads `magpie-settings.json`, and freezes its settings in `magpie-active-settings.json` for the life of each session. It starts a GPU only for an authenticated inference request.
- While the session is idle, the controller periodically checks the model backend. Three consecutive failures stop the session so a dead model process does not leave the GPU allocated until the normal idle timeout.
- The controller estimates G4 cost using 10.05 compute units/hour, measured on the current account; Colab may change the actual rate. Check `colab usage` for the current rate and balance.
- The optional experimental 1M profile for ISTA with the AtomicChat patch, images and DSpark retains a 66,000 MiB expert cache. Larger caches improved filled-context short decode modestly but substantially slowed cold prefill; its conservative memory profile is retained while 512K is the default. Memory headroom is limited. See the [G4 context tuning measurements](../../docs/benchmarks/colab-1m-20261106.md) for first-token latency, completed-answer checks and prefix-cache behavior. Other configurations retain their existing cache settings.
- `panel.py` listens on `127.0.0.1:18082` and serves status, settings and a bounded tail of the controller's local `llm.log`. The page can pause or resume its five-second log refresh and refresh status manually from the header. Logs are read locally, with secrets redacted; reading them does not contact or wake Colab. Run it under the same unprivileged account and `LLM_STATE` as the controller. Magpie's page service proxies access to this endpoint; do not expose this port publicly.
- `refresh.py` runs as Magpie's unprivileged user, with Magpie's `HOME` and `XDG_*` environment, and refreshes the custom provider's model catalog when the effective context, image input or model changes. Set `MAGPIE_BIN` and `COLAB_MAGPIE_PROVIDER` if their defaults do not match the installation. It reads loopback status and does not start a Colab session.
- Install the plugin folder with `magpie plugin add /absolute/path/to/integrations/magpie_colab` and enable it. Its host entry is needed by Magpie's page-service proxy. Launch the controller and panel under your service manager and arrange the CLI binary and runtime state with `LLM_COLAB`, `LLM_STATE` and `HOME` as needed. Restart the panel after updating its HTML.

The page offers three context tiers: 262,144 tokens per request with two decoder slots, 524,288 with one, and experimental 1,048,576 with one. All accept at most four in-flight inference requests, including cold-start waiters and backend queueing; an additional request gets HTTP 429 and can retry after one completes. Four accepted requests are not four full-window decodes at once. The default tier is 524,288, with ISTA + AtomicChat, images, DSpark and maximum reasoning effort enabled.

The same patched-ISTA/image/DSpark combination at 262,144 uses two decoder slots, UBATCH=1024, a 73,000 MiB MoE cache and DYN=166. Complete short-code throughput increased from 112.29 to 121.46 tok/s in three-repeat tests; actual 229K-input complete code improved from 104.85 to 108.70 tok/s in one sample. Cold prefill was about 7% slower, with more RAM/VRAM headroom. Other model/feature combinations retain their existing layout. See the [256K measurements](../../docs/benchmarks/colab-256k-20261106.md) for sampling settings, output differences and concurrency limits.

The patched ISTA image-and-DSpark configuration at 524,288 uses one decoder slot, UBATCH=512, a 70,430 MiB MoE cache and DYN=110. Matched-output short tests improved decode throughput by about 10–20% over the previous 64,000/50 cache profile; a synthetic 524K input, image probe and four-request queue also passed. Other model variants and feature combinations retain the conservative long-context profile. These checks do not establish long-document reasoning accuracy or sustained reliability.

The controller supplies a 32,768-token output budget when omitted and accepts smaller request budgets. It rejects larger or invalid budgets with HTTP 400 before acquiring a GPU; Chat Completions aliases `max_completion_tokens` and `n_predict` are normalized to `max_tokens`. The budget includes reasoning and visible text. Maximum reasoning can consume the entire budget without a visible answer; increasing the budget does not guarantee completion. Add the corresponding client metadata with `magpie model output 'colab-ds41/*' 32768` (use your own provider id if different).

The page shows suggested client compaction thresholds of 220,000, 460,000 and 950,000 tokens for the 256K, 512K and 1M tiers respectively, leaving room for output and tool results. These are client settings, not a server-side history truncation policy. Configure the client that performs compaction; setting a model window alone does not guarantee those exact trigger values.

Earlier saved contexts are retained for an already-running session. For the next session, legacy 32K/64K/128K settings map to the 262,144 tier; saved 256K, 512K and 1M choices are preserved. Saved changes apply to the next session; an active session keeps its original snapshot. The idle timer starts after the last request completes; the maximum runtime is a local forced-stop threshold and can interrupt active requests. Google may end a session earlier. A 24-hour selection does not guarantee eligibility or duration. The minimum balance is checked at startup and is not a spending cap.

For the page-service design, see [Magpie's plugin documentation](https://usemagpie.ai/docs/plugins) and the [community chat page](https://github.com/Magiczerowxy/magpie-chat). Treat the Colab OAuth token and all gateway keys as secrets; do not include them in plugin configuration or repository files.
